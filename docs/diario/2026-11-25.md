## Paso 2 · Adaptador de WhatsApp Cloud API
- **Qué se hizo:** `src/adaptadores/whatsapp-cloud.js`, el **único** módulo que conoce el formato de Meta (lo pide el caso para poder cambiar de proveedor sin reescribir la plataforma). Tiene tres funciones:
  - `verificarSuscripcion`: responde la verificación del webhook solo si `hub.mode` es `subscribe` y el token coincide.
  - `firmaValida`: calcula el HMAC SHA-256 del cuerpo crudo con el App Secret y lo compara en tiempo constante con `X-Hub-Signature-256`.
  - `extraerEventos`: convierte el payload de Meta en objetos internos: mensajes entrantes (id de WhatsApp, `wa_id` del cliente, nombre, tipo, texto, fecha) y estados de mensajes enviados (estado y errores).
- **Pruebas:** `test/adaptador-whatsapp.test.js` con 4 pruebas y datos ficticios: firma correcta/alterada/ausente, verificación con token correcto/incorrecto, conversión de un mensaje y de un estado fallido, y payloads ajenos ignorados.
- **Resultado:** `npm test` → 6 pruebas, 6 pasan.
- **Archivos:** `src/adaptadores/whatsapp-cloud.js`, `test/adaptador-whatsapp.test.js`.

## Paso 3 · Webhook completo con control de duplicados
- **Parte del correo que cumple:** «Recepción: un webhook de WhatsApp Cloud API que recibe mensajes de texto, valida la firma X-Hub-Signature-256 y el token de verificación, responde 200 en menos de 5 segundos y no guarda dos veces el mismo mensaje (usen el id del mensaje de WhatsApp)». Criterios 2 y 3. Indicación de Alex: «deja funcionando el control de duplicados con una prueba que muestre qué pasa si llega dos veces el mismo mensaje».
- **Qué se hizo:**
  - `src/nucleo/mensajes.js`: `guardarMensajeEntrante` crea o actualiza la conversación del cliente y guarda el mensaje con `ON CONFLICT (wa_message_id) DO NOTHING`, dentro de una transacción. Devuelve si se guardó o si era repetido. `actualizarEstadoEnvio` registra el estado de los mensajes que se envíen (sent, delivered, read, failed).
  - `src/app.js`: aplicación Express con `GET /webhook` (verificación) y `POST /webhook`: sin firma válida responde **401 sin guardar nada**; con firma válida guarda y responde 200. Si el mensaje es repetido también responde 200, para que Meta no siga reintentando.
  - `src/servidor.js` y `npm start`: arranque con el `.env`; la base se crea en `data/bandeja.db` (ignorada por Git).
  - `test/webhook.test.js`: 5 pruebas de punta a punta (HTTP real en localhost, base en memoria, datos ficticios): sin firma → 401 y 0 registros; firma con otro secreto → 401 y 0 registros; firma válida → 200, mensaje y conversación guardados, en menos de 5 s; **mismo mensaje dos veces → 200 y 200, 1 solo registro**; verificación GET correcta/incorrecta.
- **Decisión:** se guarda antes de responder 200. SQLite tarda milisegundos (las pruebas responden en ~20 ms), así el mensaje nunca se pierde: si fallara el guardado se responde 500 y Meta reintenta.
- **Resultado:** `npm test` → **11 pruebas, 11 pasan** (criterio 12: al menos 8). `npm start` arranca con el `.env` real.
- **Archivos:** `src/nucleo/mensajes.js`, `src/app.js`, `src/servidor.js`, `test/webhook.test.js`, `package.json`.

## Paso 4 · Demostración del control de duplicados contra el servidor real
- **Parte del correo que cumple:** criterio 3 «Si el mismo mensaje llega dos veces, solo se guarda una» (se comprueba con «Reenvío del payload con curl») y criterio 2 «rechaza una petición sin firma válida (401 o 403) y no guarda nada» («curl sin firma»). Indicación de Alex: compartir qué funciona y dónde revisarlo.
- **Qué se hizo:** `scripts/demo-duplicados.mjs`. Con el servidor corriendo (`npm start`), manda un mensaje **ficticio** al webhook tres veces: sin firma, con firma válida y el mismo otra vez; después de cada envío cuenta cuántas veces quedó guardado en SQLite. Cada corrida usa un id de mensaje distinto, así se puede repetir.
- **Resultado (servidor real, base `data/bandeja.db`):**
  - Sin firma → HTTP 401 · registros en la base: 0
  - Con firma (1.ª vez) → HTTP 200 · registros en la base: 1
  - Mismo mensaje otra vez → HTTP 200 · registros en la base: 1
  - Consola del servidor: «petición rechazada por firma inválida o ausente (401). No se guardó nada» · «mensaje guardado» · «mensaje repetido; ya estaba guardado, se ignora».
- **Cómo lo revisa otra persona:** `npm start` en una terminal y `node --env-file=.env scripts/demo-duplicados.mjs` en otra.
- **Archivos:** `scripts/demo-duplicados.mjs`.
