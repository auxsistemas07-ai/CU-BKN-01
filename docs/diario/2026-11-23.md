## Paso 6 · Script que envía la plantilla hello_world
- **Documentación revisada (2026-11-23):**
  - Versiones de Graph API: https://developers.facebook.com/docs/graph-api/changelog/versions → la más reciente es **v26.0** (29/07/2026); v25.0 vigente hasta 2028.

  - Get started: https://developers.facebook.com/docs/whatsapp/cloud-api/get-started → menciona hello_world, pero su ejemplo usa una versión anterior (v23.0).
- **Decisión:** usar `GRAPH_API_VERSION=v26.0` (agregado a `.env`; no es secreto).
- **Qué se hizo:** se creó `scripts/enviar-hello-world.mjs`. Lee versión, token, ID del número y teléfono de prueba desde `.env`; valida que no falte ninguno; envía la plantilla `hello_world` (`en_US`) y muestra solo el código HTTP, el estado del mensaje y los últimos 4 dígitos del destinatario. Nunca imprime el token ni los IDs.
- **Por qué `.mjs`:** el script usa `await` fuera de funciones; con `.mjs` Node lo ejecuta como módulo sin advertencias y sin cambiar `package.json`.
- **No confirmado en la documentación:** que hello_world exista en la cuenta de prueba; se confirma al ejecutar el script.
- **Archivos:** `scripts/enviar-hello-world.mjs`, `.env` (local).
- **Token:** el token temporal del 20/11 caducó; Carlos generó uno nuevo en «Step 1. Try it out → Generar token» y lo reemplazó en `.env`.
- **Prueba:** `node --env-file=.env scripts/enviar-hello-world.mjs` → `OK HTTP 200 · estado: accepted`. Confirma que hello_world existe en la cuenta de prueba, que v26.0 funciona y que el formato del cuerpo es correcto.
- **Problema:** el mensaje no llegó al teléfono pese al «accepted».
- **Diagnóstico** (sin imprimir el número): con `to` = `52` + 10 dígitos, la respuesta trae `wa_id` = `521` + 10 dígitos (distintos). Enviando directo a `521…` Meta respondió `400 · error 131030: Recipient phone number not in allowed list`. Conclusión: el número estaba en la lista de destinatarios solo como `52…`, pero la cuenta de WhatsApp de México está registrada como `521…`; Meta acepta la petición y la entrega falla sin aviso (el aviso llegaría por webhook, que aún no existe).

- **Riesgo abierto:** el comportamiento 52/521 de México no se encontró en la documentación oficial de Meta (es conocido en la comunidad). Cómo se confirmaría: buscar en la documentación de números de teléfono / códigos de error de Cloud API o abrir un caso de soporte de Meta; en la plataforma, guardar y responder siempre al `wa_id` que entrega el webhook, no al número escrito por una persona.

## Paso 7 · Webhook mínimo
- **Documentación revisada (2026-11-23):**
  - https://developers.facebook.com/docs/graph-api/webhooks/getting-started → verificación por GET con `hub.mode=subscribe`, `hub.verify_token` y `hub.challenge` (se responde el challenge); notificaciones POST firmadas en `X-Hub-Signature-256` con formato `sha256=<hex>` usando el App Secret; responder `200 OK`; Meta reintenta hasta 36 h si falla.
  - https://developers.facebook.com/docs/whatsapp/cloud-api/webhooks/payload-examples → mensaje entrante en `entry[].changes[].value.messages[]` (`timestamp`, `type`, `text.body`); estados en `value.statuses[]` (`sent`, `delivered`, `read`, `failed`, con `errors[]`: `code`, `title`).
  - https://developers.facebook.com/docs/whatsapp/cloud-api/support/error-codes → códigos de error de entrega (131026, 131047, 131049, 130497, etc.).
- **Qué se hizo:** se creó `src/webhook-minimo.mjs` con Express:
  - `GET /webhook`: responde el challenge solo si `hub.mode` es `subscribe` y el token coincide con `VERIFY_TOKEN`; si no, 403.
  - `POST /webhook`: lee el cuerpo crudo, calcula HMAC SHA-256 con `APP_SECRET` y lo compara en tiempo constante con `X-Hub-Signature-256`. Sin firma válida responde 401 y no procesa nada. Con firma válida responde 200 de inmediato y después muestra en consola solo la hora y el texto de cada mensaje.
  - Además muestra el **estado de entrega** de los mensajes enviados (y el código de error si falla), sin IDs ni números. Se agregó para diagnosticar por qué hello_world no llega.
- **Decisión:** es un webhook temporal de la mañana 1; el completo (con base de datos y control de duplicados) se hace en la mañana 3.
- **`.env`:** Claude generó un `VERIFY_TOKEN` aleatorio y lo guardó sin mostrarlo. Falta `APP_SECRET` (lo copia Carlos desde Meta).
- **Archivos:** `src/webhook-minimo.mjs`, `.env` (local).
- **Prueba local** (Carlos llenó `APP_SECRET`; Claude levantó el webhook y le mandó peticiones con un payload ficticio):
  - GET con token correcto → 200 y devuelve el challenge ✅
  - GET con token incorrecto → 403 ✅
  - POST sin firma → 401 ✅ · POST con firma falsa → 401 ✅ (no se procesa nada)
  - POST con firma válida → 200 en 5 ms ✅
  - La consola muestra solo hora y texto del mensaje y el estado con su código de error; se comprobó que no aparecen secretos ni IDs ✅
  - Nota: la primera corrida falló porque la prueba no esperó a que el servidor terminara de arrancar; se corrigió esperando el mensaje «escuchando».
