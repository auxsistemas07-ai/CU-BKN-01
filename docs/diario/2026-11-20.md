## Paso 2 · Registro como desarrollador en Meta for Developers

## Paso 3 · Crear la app y agregar WhatsApp (bloqueado temporalmente)
- **Qué se hizo:** se inició la creación de la app con el caso de uso «Connect with customers through WhatsApp». Meta pidió un portafolio comercial; al intentar crear «Pruebas CU-BKN-01», Meta respondió «Facebook Account Too New To Create A Business… Try again in an hour».
- **Por qué:** la cuenta de WhatsApp de prueba y el número de prueba viven dentro de un portafolio; se crea sin verificar.
- **Estado:** en espera de al menos 1 hora. Si el bloqueo sigue, se avisa al director. Registrado como fila 3a en `docs/simulacion-cliente.md`.
- **Actualización:** pasado el tiempo de espera, Meta permitió crear la cartera de negocios **«Cu-Bkn-01»** (sin verificar, nombre genérico) y se seleccionó en el asistente de creación de la app.
- **App creada:** «Bandeja CU-BKN-01», caso de uso de WhatsApp, estado «Inédito» (sin publicar). No se activó «proveedor de tecnología» ni la verificación del negocio.
- **Número de prueba:** en «Basic setup → Step 1. Try it out», Meta marcó «Solicita un número de prueba de WhatsApp» como terminado (número +1 555…, cuenta de WhatsApp de prueba creada). Paso 3 terminado.

## Paso 4 · Teléfono de prueba como destinatario y token temporal
- **Qué se hizo:** Carlos registró y verificó su teléfono de prueba en «Beneficiario» (código recibido por WhatsApp y escrito solo en el panel de Meta), generó el token temporal y llenó en `.env` `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` y `TEST_RECIPIENT_PHONE`. Claude agregó `PORT=3000`.
- **Verificación:** se revisó el `.env` con un script que solo informa si cada variable está llena y si su formato es correcto, sin mostrar valores. `.env` sigue ignorado por Git.
- **Por qué:** el número de prueba solo puede enviar a destinatarios verificados, y el script del paso 6 necesita token e identificadores leídos desde `.env`.
- **Archivos:** `.env` (local, no se sube).

## Paso 5 · Repositorio mínimo (adelantado mientras se libera el paso 3)
- **Qué se hizo:** se crearon `package.json` (Node >= 20.6, sin dependencias aún), `.gitignore` (ignora `.env`, `.env.*` salvo `.env.example`, y `node_modules/`) y `.env.example` solo con nombres de variables.
- **Por qué:** dejar la base del proyecto lista y garantizar desde el inicio que los secretos no entren a Git.
- **Archivos:** `package.json`, `.gitignore`, `.env.example`.
- **Ejecutado:** `git init` (rama `main`), `npm install express` (Express 5.3.0, 0 vulnerabilidades), `.env` creado vacío y confirmado como ignorado (`git check-ignore`). Remoto `origin` conectado al repositorio de GitHub del caso. Identidad de Git configurada solo a nivel del repositorio.
- **Commit y push:** hechos por Carlos (`b92d8f4`). Para que Git usara la cuenta del caso y no otras guardadas en el equipo, se fijó el usuario `auxsistemas07-ai` en la URL del remoto y en `credential.username` (solo en este repositorio).
